# 手 · whalelife-plugin-hands

给 WhaleLife 装上的一双手：列目录、读文件、写文件、跑本机命令。

WhaleLife 主干只负责对话与插件框架，碰不到硬盘。这个插件补上那一层，
让助手能真的动文件、跑 node、查端口——但只在允许的根目录里动。

> **这是高权限插件。** 装上之后，模型可以读写你允许目录里的任何文件、执行任意命令。
> 先读完下面的「边界」一节再决定装不装。

## 工具

| 工具 | 作用 | 危险级 |
|---|---|---|
| `hands_list` | 列目录，`depth` 最多 3 层 | safe |
| `hands_read` | 按行读文本文件 | safe |
| `hands_write` | 写或追加文本，自动建父目录；覆盖前留副本，可带 `expected_sha256` 版本比对 | 需确认 |
| `hands_run` | 跑 PowerShell 脚本，可带 `verify_files` 写后核验；输出只当轮可用 | 危险 |

## 环境要求

- WhaleLife 宿主，插件 API `1.x`
- Windows（`hands_run` 调 `powershell.exe`；其余三个工具跨平台）
- 不需要其它插件，`depends` 为空

## 安装

### 手动安装

把本仓库的 `index.ts` 和 `plugin.yaml` 放进宿主的插件目录：

```
<宿主目录>/plugins/hands/
├── plugin.yaml
├── index.ts
└── data/            # 首次运行时自动创建
```

然后在控制台「插件管理」里启用 `hands`。
宿主目录就是 WhaleLife 仓库根，`index.ts` 里的 `../../core/context.ts` 按这个位置解析。

### 商店安装

如果本插件已被社区目录收录，可在控制台商店直接安装。
本仓库的 Release 里带有 `.wlpkg.gz` 发行包，发行说明写了大小和 SHA-256。

## 配置

配置文件：`plugins/hands/data/config.json`

```json
{
  "roots": ["D:\\我的工作区"],
  "timeout_ms": 60000,
  "max_output_chars": 20000
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `roots` | `[]` | 允许操作的根目录列表。**留空时回落到宿主自己的工作目录。** 写 `"*"` 表示不限制，非常不建议 |
| `timeout_ms` | `60000` | 单条命令超时 |
| `max_output_chars` | `20000` | 输出超过这个长度就掐头去尾保留中间提示 |
| `backup_keep_days` | `30` | 覆盖前副本保留天数，过期自动删 |
| `backup_max_bytes` | `1073741824` | 副本目录总量上限，超了从最旧的删 |
| `deny_patterns` | 见源码 | 命中即拒绝的命令片段，如 `format `、`diskpart`、`reg delete` |

写进 `config.json` 的键会覆盖默认值；没写的键沿用默认。

## 边界

- **路径闸**：四个工具的每个路径参数都要落在 `roots` 之内，越界直接报错，不静默改成别的路径。
- **拒绝清单**：`deny_patterns` 里的片段出现在命令里就拒跑。这是防手滑，不是安全边界——真要防，靠的是 `roots` 只开一个专门的目录。
- **没有沙箱**：`hands_run` 跑的是你当前用户的权限。它拦不住一个存心使坏的模型，只能拦住"模型不知道自己在干什么"。
- **建议**：单独开一个目录给助手用，`roots` 只指向它；重要的东西放在外面。

## 用法示例

用户说"看看下载目录里有什么"。

```
hands_list { "path": "Downloads" }        // 相对路径按 roots[0] 解析
```

改动文件并当场核验：

```
hands_run {
  "command": "$value = 42; Write-Output \"值=$value\"",
  "verify_files": [{ "path": "out.txt", "contains": ["值=42"] }]
}
```

`verify_files` 会在命令跑完后回读文件，逐条报告哪个字面量在、哪个不在。
说"写好了"必须有这个回执，否则只能说"命令执行过，文件未验证"。

详细用法见 [`docs/使用手.md`](docs/使用手.md)。

## 踩过的坑

每一条都写清**现象 → 原因 → 修补**，方便以后改 `runShell` 时不用重新踩一遍。

### 1. 命令里的 `$value` 被吃掉

**现象**　发 `$value = 42; Write-Output "值=$value"`，回来的是 `值=`，变量像是凭空没了。
长度不报错、退出码 0，就是内容凭空少一段。更糟的是带引号拼路径时，路径静默变成一个残缺的字符串，
命令照样"成功"。

**原因**　原先用 `execFile("powershell.exe", ["-Command", command])`。
`-Command` 的实参要先过一层 Windows 命令行解析，双引号里的 `$` 在 PowerShell 看到之前就被外层处理掉了。
这跟 PowerShell 的引号规则无关，是穿了两层壳。

**修补**　不再拼命令行字符串。每次调用把脚本写进 `%TEMP%\hands-<随机>.ps1`，再用
`powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <那个文件>` 跑。
`-File` 的参数是平面参数，脚本内容不经过命令行解析，`$` 原样进入脚本。

### 2. 中文输出乱码

**现象**　`Write-Output "测试"` 回来是一串 `锟斤拷` 或 `娴嬭瘯`。

**原因**　Windows PowerShell 控制台默认按系统 ANSI 代码页（简体中文是 GBK，如 936）输出字节，
而插件按 UTF-8 解码。麻烦在于**不能无脑"先试 UTF-8、失败再试 GBK"**——「值」的 GBK 字节
（`D6 B5`）恰好也是合法 UTF-8 序列，严格解码不会失败，解出来却是别的字，静默出错。

**修补**　顺序反过来：先严格 UTF-8 解，解出来若落在可疑区段（私用区、替换符、连续高位），
再回退重试 GBK。判不出来的情况下宁可报"编码不明"，也不猜一个像样的结果。

### 3. 临时 .ps1 的 BOM：和配置文件正好相反

**现象**　脚本里写中文注释或中文字符串，`-File` 执行时报解析错误，或者中文变成乱码，
报错信息还指向一个看起来没错的行。

**原因**　Windows PowerShell 5.1 读**没有 BOM** 的 `.ps1` 时按系统 ANSI 代码页解析。
文件是 UTF-8 写的，没 BOM，中文就按 GBK 解释。

**修补**　临时脚本一律写成**带 BOM 的 UTF-8**。注意这条只针对 `.ps1`：
`config.json`、`plugin.yaml`、`.md` 这些配置文件必须**不带 BOM**，否则别的解析器会把 BOM 当成内容。
一个插件里两种规矩并存，容易搞混，所以写在这里。

### 4. 失败的命令返回退出码 0

**现象**　命令明明报了错（红字一大段），回执却是"退出码 0"，于是被当成成功往下走。

**原因**　PowerShell 默认不因为非终止性错误改变进程退出码。走 `-Command` 时，
即使语句报错，进程通常仍以 0 结束。

**修补**　脚本末尾固定追加一行 `if (-not $?) { exit 1 }`。
只要最后一条语句失败，进程就带非零码返回。判断成败看退出码，不看有没有输出。

### 5. 工具抛异常会把整个插件撤掉

**现象**　某次调用里文件不存在，结果**四个工具全没了**，插件页显示异常，只能重载插件。

**原因**　宿主的 worker 包装器把工具抛出的异常视为插件故障，会撤销该插件的全部工具入口。
一处小错，满盘皆输。

**修补**　所有工具函数都过一层 `safe()`：抛出的异常在插件内收口，变成 `错误：<原因>` 的文本返回。
读文件那条也做了区分——只有 `ENOENT` 才算"本来就不存在"，别的读错误必须原样报出来，不能当成空文件。

### 6. 写文件用 PowerShell 重定向，编码不可控

**现象**　`Out-File`、`>`、`Set-Content` 写出来的文件，换行是 CRLF、编码是 UTF-16 或 ANSI，
下游 `JSON.parse` 直接失败。

**原因**　PowerShell 各版本这些 cmdlet 的默认编码不一样，5.1 和 7 不同，重定向 `>` 又是另一套。

**修补**　写文件不走 shell，用 `node:fs` 的 `writeFile` 显式写 UTF-8。
真要由 shell 写，就 `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`。
写完必须回读一次，拿到字节数或行号才算写成。
### 7. 命令输出把长期记忆撑爆

**现象**　跑一次 `Get-ChildItem -Recurse` 或者读一份大日志，接下来几轮对话都吃力，
上下文里全是那段输出；过几天回头，还记得当时屏幕上每一条文件，却记不得为什么跑它。

**原因**　工具结果默认走 `register`，整段返回值进消息历史与记忆。`hands_run` 的输出常常几万字符，
对长期记忆几乎没有价值，有用的只有「跑过什么、成没成」。

**修补**　改用宿主的 `registerTransient`：正文（`content`）只给当轮模型看，
持久化只留一条精简回执（`receipt`）——退出码、目录、命令抬头、核验统计，不含 stdout。
宿主没有这个接口时退回 `register`，不做静默降级假装它是临时的。
需要留档的输出，写进文件，别指望从记忆里捞。

### 8. 覆盖文件把别人的改动盖掉

**现象**　助手改了一个文件，几个小时后才发现是在一份过时的内容上改的；
中间别人（或另一个窗口）已经改过，改动被静默覆盖，无从找回。

**原因**　`hands_write` 直接 `writeFile`，既不留旧副本，
也不检查「我看到的版本还是不是现在这个版本」。

**修补**　两层：

- 覆盖或追加已有文件前，先把原始字节写到 `data/backups/<时间戳>-<sha前8>-<文件名>`，
  按 `backup_keep_days`（默认 30 天）和 `backup_max_bytes`（默认 1 GiB）自动清理，删最旧的。
  备份失败就中止写入，不假装已经留了退路。
- 支持 `expected_sha256`：给了就先比对当前文件哈希，不符直接拒写，并报出两边的前 12 位。
  读完文件、决定改之前，把读到的哈希带上。

```
node test/smoke.mjs
```
